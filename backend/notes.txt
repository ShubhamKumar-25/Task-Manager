TASK MANAGEMENT CRUD + JWT AUTHENTICATION — SUMMARY

1. PROJECT GOAL
----------------
Built a real-world Task Management backend instead of repeatedly practicing User CRUD.
The project uses MVC architecture and includes:
- Task CRUD operations
- PUT and PATCH updates
- MongoDB + Mongoose
- JWT authentication
- Password hashing with bcryptjs
- Protected task routes
- User-specific tasks

2. TASK MODEL
-------------
Task fields:
- title: String, required, trim
- description: String, required, trim
- priority: String, enum ["Low", "Medium", "High"], default "Medium"
- status: String, enum ["Pending", "In Progress", "Completed"], default "Pending"
- dueDate: Date, required
- user: ObjectId, ref "User", required
- timestamps: true

The user field connects every task to the user who created it.

3. USER MODEL
-------------
User fields:
- name: String, required, trim
- email: String, required, unique, trim, lowercase
- password: String, required
- timestamps: true

Passwords must be hashed before storing them in MongoDB.

4. TASK CRUD APIs
-----------------
POST   /api/tasks          -> Create task
GET    /api/tasks          -> Get logged-in user's tasks
GET    /api/tasks/:id      -> Get one task
PUT    /api/tasks/:id      -> Complete/full task update
PATCH  /api/tasks/:id      -> Partial task update
DELETE /api/tasks/:id      -> Delete task

5. PUT VS PATCH
---------------
PUT:
- Used for complete/full resource update.
- Usually sends all task fields.

PATCH:
- Used for partial update.
- Example: only update status:
  { "status": "Completed" }

For Mongoose updates:
{
    returnDocument: "after",
    runValidators: true
}

returnDocument: "after" returns the updated document.
runValidators: true applies schema validation during updates.

6. AUTHENTICATION APIs
----------------------
POST /api/auth/signup
Body:
{
    "name": "Shubham",
    "email": "shubham@gmail.com",
    "password": "123456"
}

Signup flow:
Request -> Validate fields -> Check existing user -> Hash password with bcrypt -> Create user.

POST /api/auth/login
Body:
{
    "email": "shubham@gmail.com",
    "password": "123456"
}

Login flow:
Request -> Find user -> Compare password with bcrypt -> Generate JWT -> Return token.

7. JWT AUTHENTICATION
---------------------
JWT contains the user's ID:
{
    userId: user._id
}

Token is signed using:
process.env.JWT_SECRET

Example:
Authorization: Bearer YOUR_TOKEN

The auth middleware:
1. Reads Authorization header.
2. Extracts Bearer token.
3. Verifies JWT.
4. Stores decoded data in req.user.
5. Calls next() if token is valid.
6. Returns 401 if token is missing, invalid, or expired.

8. USER-SPECIFIC TASKS
----------------------
Instead of:
Task.find()

Use:
Task.find({
    user: req.user.userId
})

When creating a task:
user: req.user.userId

This means each task belongs to a specific logged-in user.

For update/delete/get-by-id, use both:
{
    _id: taskId,
    user: req.user.userId
}

This prevents one user from accessing or modifying another user's tasks.
